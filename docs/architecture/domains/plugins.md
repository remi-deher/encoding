# Plugins, composants et outils média

Les manifestes de toutes les familles historiques sont distribués par le dépôt public [Encoding Store](https://github.com/remi-deher/encoding-store) : base 1.10.1, nodes 1.8.1, conditions 1.2.1, video 1.3.2, audio 1.1.2, subtitles 1.3.2, mkv 1.1.2, images 1.0.2, ai 1.0.2, probe 1.1.2, Plex 1.1.0, Sonarr/Radarr/Jellyfin 1.0.0. Les handlers de `base`, `nodes`, `conditions` et des familles média restent dans le moteur C# ; les paquets natifs distribuent leurs manifestes et dépendent de ces handlers.

## Contrat
- **Effets média** (ADR [0011](../adr/0011-controles-media-selon-effets.md)) : `mediaEffect` optionnel dans le descripteur : `readOnly` interdit un candidat ; `producesOutput` impose un candidat distinct et préserve l'entrée ; `modifiesCurrent` soumet toujours le fichier courant à validation, même à taille/date identiques. Le moteur choisit les contrôles et conserve SHA-256 pour les transferts et publications. Sans déclaration : résultat explicite et détection taille/dernière modification pour compatibilité. La déclaration ne vaut jamais permission d'écrire dans la bibliothèque ni garantie d'idempotence. Elle participe à l'empreinte du contrat annoncée par le worker (version de plugin à incrémenter lors de son adoption).
- `readOnly` + `requiresMedia: false` + aucune production de fichiers permet une invocation sur les métadonnées sans copie média, sans `currentArtifactId` et sans accès à la source. Les autres plugins reçoivent une copie de travail. La vérification des effets lecture seule/nouveau fichier utilise taille/date et ne remplace pas Landlock ; une modification volontaire qui conserve taille/date doit être signalée explicitement.
- Un plugin déclare identité, version, compatibilité hôte (`supportedHostContractVersions`) et composants (`PluginManifest`, `FlowComponentDescriptor`). Un composant : `id`, `version`, `category` fonctionnelle (`inputs|files|discovery|metadata|encoding|video|audio|images|text|containers|media-rules|validation|conditions|variables|scripts|arr|media-servers|communications|cluster|orchestration|reporting|utilities`), `kind` (`action|condition|…`), types de flow compatibles, `requiresMedia`/`requiresWriteAccess`, **sorties** (`id`, `label`, `description`) et `configurationSchema` déclaratif v1 (`text|number|boolean|select|condition-tree|record-list…`, `inline`, `importance`, `section`, visibilité conditionnelle, bornes, défauts). La catégorie organise le catalogue sans changer l'exécution ni l'empreinte de capacité du worker. Elle reste facultative pour les plugins tiers existants ; une valeur inconnue est rejetée. **Aucun code d'interface** dans un plugin ; le frontend rend les schémas avec le formulaire commun.
- Pour que l'IA et MCP assemblent des flows sans erreur : description claire du composant, **chaque sortie et chaque champ décrits** (unités, bornes, défaut sûr), ids de sortie stables (`success`, `error`, `unchanged`…). Un composant sans descriptions est un défaut.
- Évolution : tout changement de comportement incrémente la version du plugin, garde les versions précédentes résolubles (`compatiblePluginVersions`) et un worker n'annonçant pas la version requise (`plugin/<id>` + version) ne reçoit pas le flow (pendant une mise à jour progressive les flows attendent un worker à jour). Un composant ou une option peut exiger une version minimale.
- Configuration à deux niveaux : **plugin** (défauts du cluster) puis **dérogation par flow** (révision propre), plus les paramètres d'**instance** du bloc. Valeurs effectives fusionnées à l'attribution et figées pour la tâche. Secrets chiffrés en base, jamais dans exports/sauvegardes/événements/journaux ; un champ `"scope": "server"` ne quitte jamais le serveur (ex. `webhookSecret`). Test de connexion depuis le serveur (ne prouve pas l'accès depuis les workers).

## Activation cluster (ADR [0021](../adr/0021-activation-cluster-plugins-outils.md))
- Les switchs de Plugins & Outils modifient une préférence cluster enregistrée dans les registres LWW existants. L’activation est la valeur par défaut ; `base` et `nodes` ne peuvent pas être désactivés.
- Désactiver un plugin bloque la publication et l’exécution de nouveaux traitements, et son éligibilité aux nouvelles attributions. Les brouillons existants restent modifiables. Désactiver un outil exclut sa capacité des nouvelles attributions. Une exécution déjà commencée, y compris une reprise à checkpoint ou une sonde différée, peut terminer.
- Cette préférence converge éventuellement : un serveur isolé peut conserver son état connu jusqu’à réception de l’événement. L’installation et le Store de paquets tiers restent locaux à chaque serveur ; le switch ne supprime aucun paquet.

## Exécution et isolation
- Plugins tiers : **processus séparé** (jamais chargés dans ASP.NET ou l'agent), protocole stdin/stdout versionné (`describe`, `execute`, `contractVersion` 1), réponses bornées, sous **Landlock** ([runtime.md](runtime.md)). Runtimes : `python3` (stdlib, SDK `encoding_plugin_sdk.py`) et `node` (SDK `encoding-plugin-sdk.mjs`). Pas de plugin .NET : jamais démarré sous Landlock réel, non vérifié.
- `ProcessSandbox.MinimalEnvironment` : liste blanche d'environnement. `/proc` et `/sys` sont lisibles dans le bac à sable (décision de sécurité ouverte : [open-questions.md](../open-questions.md)).
- La capacité `plugin/<id>` n'est annoncée qu'après poignée de main réussie (avec empreinte du contrat comparée au serveur).

## Store de plugins et d'outils (ADR [0029](../adr/0029-store-plugins-outils-hashes.md), migration historique [0030](../adr/0030-migration-composants-et-plugins-historiques-au-store.md))
- Paquet `.zip` : `plugin.json` à la racine = `PluginManifest` + bloc `runtime` (`{type: python3|node, entrypoint}`), ou `{type: native, entrypoint: ""}` pour les familles moteur `base|nodes|conditions|video|audio|subtitles|mkv|images|probe|ai` ; identifiant qualifié `espace.nom` pour les plugins tiers, identifiant historique autorisé pour un paquet officiel ; limites 32 Mo compressé, 128 Mo décompressé, 500 fichiers ; chemins absolus, `..`, `:` refusés. `official.*` réservé au dépôt officiel.
- Dépôts statiques `repository.json` 1.x (validés entrée par entrée, SHA-256 obligatoire, versions publiées immuables). `plugins[]` et `tools[]` partagent le même index. L’image configure le dépôt public `remi-deher/encoding-store` via `PluginStore:OfficialRepositoryUrl` ; aucun paquet n'est installé par défaut.
- Serveur : plugins installés à chaud (`FlowComponentRegistry.TryInstall`) dans `PluginStore:Directory`. Un plugin peut déclarer `requiredToolPackages[]` avec `toolPackageId`, `minimumVersion`, `maximumVersionExclusive` et `requiredCapabilities`. Son installation depuis un dépôt installe aussi les versions compatibles publiées de ces paquets ; l'import est refusé si une dépendance reste insatisfaite.
- Paquet d'outil `.zip` : manifeste `tool.json` à la racine, contrat 1, `id`, `version`, `platform`, `executables[]` (`toolId`, chemin relatif, SHA-256 du binaire) et capacités. Limites 512 Mio compressé, 1 Gio décompressé, 2 048 fichiers ; liens symboliques et chemins sortants refusés. Le dépôt annonce aussi le SHA-256 de l'archive. Un seul paquet fournit un rôle sur une plateforme ; tous les plugins qui le déclarent partagent ce fournisseur. L'import et chaque worker vérifient le hash de l'archive et des exécutables. Le worker expose le hash vérifié dans `NodeToolCapability.ToolPackageSha256`.
- Workers : `PluginSyncService` et `ToolPackageSyncService` (chaque minute) synchronisent les archives par endpoints protégés par le jeton de nœud. Les outils sont extraits sous `Runtime:ManagedToolDirectory` (défaut `/opt/encoding/managed-tools`) ; le résolveur préfère le paquet vérifié, puis le `PATH` du système si l'opérateur a installé un outil localement ; l'image Encoding ne contient plus ces exécutables. Les plugins qui déclarent des outils requis ne sont annoncés comme capacités qu'après validation locale des dépendances. Mises à jour manuelles, jamais automatiques.
- Le Store ne préinstalle aucun paquet. Les familles média natives sont des paquets installables ; leur code d'exécution reste dans `MediaActions` et les handlers du moteur. Les paquets binaires linux-x64 Noble de FFmpeg/FFprobe, MKVToolNix, MediaInfo et ImageMagick sont publiés dans le Store. Les autres plateformes restent à publier et les dépendances matérielles restent à valider.
- Limites : l'état du Store est local à chaque serveur (non réconcilié), pas de signature, pas de réplication/synchronisation périodique des index, retrait des plugins non refusé lorsqu'un flow les utilise et Landlock en production non vérifié. L'empreinte assure l'identité du binaire reçu, pas sa provenance ni son innocuité.
- Outils d'auteur : validateur de manifeste/paquet, simulation locale, SDK JavaScript ; MCP `validate_plugin_manifest`, `validate_tool_definition`, `list_media_tools`, `get_media_tool_info` ([auth-ops.md](auth-ops.md)). Guide : `backend/plugins/README.md`.

## Composants natifs distribués par le Store (rôle, pas liste exhaustive)
- **base** : paquet natif du Store ; entrées (fichier générique + spécialisées), `base-script` (JS/Python, `useTools`), plan de traitement (`prepare`/`execute`), report, fin, variable, `base-wait`, `base-disk-lock/unlock`. L’assemblage MKV copie par défaut les pistes audio et sous-titres d’origine ; la transformation des sous-titres et l’ajout de polices sont explicites et désactivés par défaut. À installer depuis le Store ; aucun composant n'est préinstallé.
- **nodes** : paquet natif du Store ; contraintes d'attribution, `nodes-handoff`, `nodes-retry-on-worker-loss`, `nodes-require-direct-access` ([runtime.md](runtime.md)). Reconnu nativement par les workers.
- **conditions** : paquet natif du Store ; `conditions-match` (arbre ET/OU) + blocs dédiés Oui/Non/Erreur (codec vidéo/audio, résolution avec tolérance aux ratios cinéma, canaux, langue, HDR/Dolby Vision, profondeur de couleur) évalués par `MediaConditionEvaluator` sur les métadonnées scannées.
- **video / audio / subtitles / mkv / images / probe** : opérations média ; points d'attention durables : transcodage vidéo adaptatif (paliers de qualité par résolution, 10 bits automatique pour HEVC/AV1, préservation HDR par défaut), `audio-rules` (table fixe stéréo AAC / 3 canaux et plus en AC-3 ≤ 6 canaux avec LFE préservé, déduction de disposition refusée en cas de références contradictoires), noms de pistes MKV via `mkvpropedit` sur la copie de travail (sélection par UID), `mkv-edit-in-place` (langue, nom, drapeaux d'une piste modifiés dans la source, ADR 0002), sous-titres (SRT→ASS au profil proportionnel intégré « Crunchyroll », ASS personnalisé laissé intact, déduplication intelligente des polices jointes par analyse SFNT/nom normalisé sans doublon, polices depuis `ENCODING_FONT_DIR` ou, depuis `subtitles` 1.3.0, depuis une ressource du catalogue du cluster (champ `resource`, « identifiant:version » ; le worker télécharge les fichiers du serveur avec son jeton de nœud, contrôle taille et SHA-256, ajoute toutes les polices manquantes ; aucun jeu local n'est alors exigé à l'éligibilité ; ADR 0006) ; non versionnées dans le dépôt), `probe-validate-output`, garde de taille, auto-crop, désentrelacement.
- **ai** : `ai-translate-subtitles`, `ai-metadata-enricher` ([ai.md](ai.md)).
- **plex / sonarr / radarr / jellyfin** (Python, paquets du Store) : actions de flow ; **déclencheur d'import** = webhook côté serveur `POST /api/v1/integrations/{sonarr|radarr}/webhook` (secret en temps constant, fermé sans secret, 1 Mo, limitation 10 échecs/5 min, demande durable `integration_trigger_requests`, passe par la découverte et la mise en file communes ; un chemin du réseau n'est jamais exécuté sans avoir été découvert). Correspondance de chemins `LibraryPathMapping` (une définition C#, mêmes vecteurs côté Python). Clés API uniquement en en-tête, jamais dans les messages. Plex : lecture en cours (option épisode précédent), `plex-analyze-media`, garde de publication. **Assistant de configuration Plex** (ADR [0008](../adr/0008-assistant-de-configuration-plex.md)), dans l'onglet Configuration du plugin : connexion plex.tv par code PIN (`/api/v1/plugins/plex/setup/pin`, `…/pin/check`), session opaque chiffrée (clé partagée du cluster, 15 min) à la place du jeton du compte, choix du serveur et de l'adresse (`…/server`, jeton propre au serveur, vérification `/identity`), lecture des sections Plex et proposition de correspondance (`…/libraries`, règle unique `LibraryMappingSuggester` : chemin identique, sinon segments finaux communs départagés par le type, égalité jamais tranchée), enregistrement (`…/mappings`) au format `LibraryPathMapping` inchangé. Aucun jeton Plex ne transite par le navigateur ni par les journaux. Échec d'infrastructure = erreur de processus, jamais une sortie métier.

## Outils média : rôles et fournisseurs
- Les composants consomment un **rôle d'outil** (`ffmpeg`, `ffprobe`, `mkvmerge`, `mediainfo`…), jamais un chemin brut. Fournisseur géré : paquet du Store résolu par rôle et plateforme ; repli de compatibilité : outil du système fourni par l'opérateur dans le `PATH`. Le catalogue de l'éditeur (`media-tool-actions.ts`) est éditorial et n'atteste pas qu'un binaire est installé ; seul l'agent déclare outils, versions, SHA-256 du binaire géré et encodeurs vérifiés.
- Le switch d’un outil média règle son usage dans le cluster ; il ne désinstalle pas le binaire. Les nœuds retirent la capacité désactivée des nouvelles attributions après convergence de la préférence partagée.
- FFmpeg géré passe par les mêmes sondes synthétiques d'encodeur que FFmpeg de l'image. Les essais GPU réels restent à faire ; la politique d'accélération matérielle est suivie dans [todo-hardware-accelerated-tools-policy.md](../../operations/todo-hardware-accelerated-tools-policy.md).

## Invariants
1. Un plugin ne contourne ni attribution, ni accès bibliothèque, ni baux, ni scan, ni validation/publication.
2. Descriptor disponible ≠ plugin exécutable sur un worker.
3. Jamais de secret ni de chemin local dans les sorties, journaux ou exports.
4. Le flow historique reste valide quand un plugin évolue.

## Analyse pendant la composition vidéo
Depuis `video` 1.3.0, la composition FFmpeg réutilise une seule analyse de son entrée pour sélection, resize et politique vidéo ; un échec d'analyse vidéo bloque au lieu d'être ignoré. Les composants gardent `compatiblePluginVersions` pour 1.2.0 et les versions précédemment acceptées. Les nouveaux flows attendent un worker annonçant le contrat installé ; aucune migration des flows historiques.

Les plugins officiels ne sont plus copiés dans l'image. Ils sont installés depuis le Store et synchronisés vers les workers comme les autres paquets ; les intégrations de processus passent toujours par le handshake Landlock avant annonce d'une capacité. L'attribution vérifie les champs obligatoires de la configuration effective des plugins du flow avant traitement, sans diffuser leurs valeurs dans l'erreur.
